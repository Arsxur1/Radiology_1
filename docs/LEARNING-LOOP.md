# Самообучающийся контур

Центральная идея платформы: чем больше клинического материала проходит через
систему, тем лучше становятся модели — при строгом соблюдении безопасности
пациента. Это реализация FR-9 → FR-10 → FR-11 ТЗ и соответствует признанному
подходу PCCP (предварительно согласованный план изменений).

```
   Клиническая работа врача
            │
            ▼
  ┌──────────────────────┐   FR-9: разметка как побочный результат
  │  Захват правок        │   confirm / modify / reject / add
  │  services/corrections │   → таблица correction (+ было/стало, время)
  └──────────┬───────────┘
             │  накопление
             ▼
  ┌──────────────────────┐   FR-9: экспорт с фильтрами
  │  Экспорт набора       │   модальность / аппарат / возраст / качество
  │  services/dataset_export
  └──────────┬───────────┘
             │  ОТДЕЛЬНЫЙ контур обучения (не продуктив!)
             ▼
  ┌──────────────────────┐   FR-10, шаги 3–4
  │  Дообучение офлайн     │   → модель-кандидат + замороженный тест
  └──────────┬───────────┘
             ▼
  ┌──────────────────────┐   FR-10, шаг 5
  │  Теневой прогон       │   кандидат в SHADOW параллельно действующей
  │  (режим SHADOW)       │   сравнение с заключениями врачей
  └──────────┬───────────┘
             ▼
  ┌──────────────────────┐   FR-10, шаг 6 — ГЕЙТ
  │  Продвижение           │   evaluate_promotion(): все условия?
  │  services/model_registry   ├─ нет → отказ с причинами
  └──────────┬───────────┘   └─ да  → осознанное решение ответственного лица
             │                        + обоснование + аудит
             ▼
  ┌──────────────────────┐   действующая модель (ASSIST)
  │  ACTIVE               │◄── мгновенный откат к предыдущей версии в любой момент
  └──────────┬───────────┘
             ▼
  ┌──────────────────────┐   FR-11
  │  Контроль дрейфа      │   распределение входов (новый аппарат/протокол)
  │  services/drift        │   доля отклонений по срезам → сигнал деградации
  └──────────────────────┘
```

## Инварианты безопасности контура

- **Обучение никогда не идёт на продуктивном контуре** (FR-10, п. 3). Экспорт —
  единственный выход данных наружу, и он обезличен по построению (SR-9).
- **Ни одно продвижение не автоматическое.** `evaluate_promotion()` только
  проверяет условия; перевод в ACTIVE требует роли admin, обоснования и пишется
  в аудит. Авто-обновление модели в ASSIST запрещено технически (SR-3).
- **Кандидат обязан пройти SHADOW.** Гейт отклоняет любую модель не в статусе
  SHADOW — шаги 3–5 пропустить нельзя.
- **Замороженный тест** формируется до обучения и не открывается (FR-10, п. 4).
  По возможности содержит аппараты, отсутствующие в обучающем наборе (раздел 9, п. 3).
- **Мгновенный откат** (`rollback`) не требует гейта — это аварийное
  восстановление; прежние версии сохраняются (RETIRED), а не удаляются.
- **Правки — не разметка вручную.** Врач работает; каждое подтверждение,
  изменение и отклонение автоматически становится обучающим сигналом с
  сохранением исходных данных и версии модели.

## Что уже готово (этап продолжения)

| Компонент | Файл | Тесты |
|---|---|---|
| Захват правок (confirm/modify/reject/add) | `services/corrections.py`, `api/routes_findings.py` | инварианты SR-2/SR-6 в коде |
| Экспорт обучающего набора с фильтрами | `services/dataset_export.py`, `api/routes_learning.py` | `test_dataset_export.py` |
| Реестр и жизненный цикл моделей, гейт продвижения, откат | `services/model_registry.py`, `api/routes_models.py` | `test_model_promotion.py` |
| Контроль дрейфа: доля отклонений по срезам, новый аппарат | `services/drift.py`, `api/routes_learning.py` | `test_drift.py` |

## Что подключается на этапе 2+

- Реальные модели сегментации (MONAI/TotalSegmentator) — они начнут порождать
  `inference_result` и `finding`, которые врач правит; контур сразу заработает.
- Автоматический расчёт метрик замороженного теста и сравнения теневого прогона
  (сейчас свидетельства передаются в гейт явно — это точка интеграции пайплайна).
- Пороги допуска (`PromotionCriteria`) согласуются под площадку до этапа 5 (раздел 9).
