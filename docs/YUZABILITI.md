# Файл инженерии юзабилити (IEC 62366-1) — проект

**Проект для регуляторного консультанта и клинического руководителя пилота NCMC.** Связывает
интерфейс с файлом рисков (`UPRAVLENIE-RISKAMI.md`): какие ошибки использования могут
привести к вреду, какие элементы интерфейса их предотвращают, и как это проверить на врачах
NCMC в пилоте. Места, требующие решения, отмечены **«Решить»**.

Редакция от 4 октября 2026 г.

## 1. Спецификация использования

| | |
|---|---|
| Медицинское назначение | помощь врачу-рентгенологу: находки-черновики и измерения для проверки, сравнение в динамике, черновик заключения (`TEKHNICHESKIY-FAYL.md`, п. 2) |
| Пациенты | дети 0–18 лет (NCMC); модель работает только в своих границах (SR-7) |
| Пользователи | **врач-рентгенолог** (основной: решения по находкам, подпись); **клиницист** (просмотр, подписанные заключения, раскрытие личности по цели); **администратор** (режимы, модели, сопоставление пациентов, инциденты, отзыв согласия); **аудитор** (журналы). Подготовка: врачи — специалисты по лучевой диагностике; ИИ-инструменты в работе — **Решить** (опросить до пилота) |
| Язык | интерфейс — русский; заключение — русский или узбекский (`GLOSSARY-UZ.md`) |
| Среда | кабинет описания NCMC: рабочая станция, браузер, рядом PACS-просмотрщик; смены, срочные исследования; сеть NCMC |
| Принцип действия | черновик ИИ → врач подтверждает, исправляет или отклоняет **каждый** → заключение только из подтверждённого → подпись |

## 2. Элементы интерфейса, связанные с безопасностью

Каждый элемент — мера из файла рисков; проверяется автотестом и будет проверен на врачах.

| Элемент | Где | Против какой ошибки | Риск |
|---|---|---|---|
| Баннер режима на каждом экране (RESEARCH / SHADOW / ASSIST с пояснением) | `ModeBanner.tsx` | врач не понимает, видит ли он ИИ | R-16 |
| Метка «черновик ИИ — требует подтверждения» на каждой находке модели | `FindingCard.tsx` | черновик принят за решение врача | R-01 |
| Уверенность модели с подсказкой «оценка модели, а не вероятность диагноза» и порогом показа | `FindingCard.tsx` | уверенность принята за вероятность болезни | R-01 |
| Решение по каждой находке отдельно; «принять всё» нет; отклонение — одно действие, причина по желанию потом | `FindingCard.tsx`, SR-2, SR-6 | массовое принятие без проверки; отказ от отклонения из-за «трудно» | R-01 |
| Подпись невозможна, пока есть черновики ИИ без решения (сервер перечисляет какие) | `report_repo.finalize_report` | подпись с непросмотренными черновиками | R-01 |
| Заключение собирается только из подтверждённых находок; отметка «ИИ → подтверждено врачом» | `report_draft.py`, `report_export.py` | в заключение попало непроверенное | R-01 |
| При пустой серии: «Отсутствие черновиков ИИ не означает отсутствие патологии» | `StudyReview.tsx` | пустой экран принят за «норму» | R-03 |
| **Отказ ИИ на серии виден врачу** с причиной: «ИИ не анализировал эту серию… вне границ применимости» (с 4 октября) | `StudyReview.tsx`, `GET /studies/{id}` → `ai_refusals` | «ИИ не смотрел» принято за «ИИ не нашёл» | R-03, R-07 |
| Тепловая карта по кнопке «Зона внимания ИИ», подпись «не разметка патологии и не измерение» | `FindingCard.tsx` | карта принята за разметку | R-04 |
| Предупреждение «Пациент не сопоставлен однозначно… прошлые исследования могут не отображаться» | `StudyReview.tsx` | неполная динамика принята за полную | R-05 |
| Пометка серии «возможен текст с данными пациента на снимке» | `StudyReview.tsx` | — (данные) | R-19 |
| Раскрытие личности только с выбором цели, «Скрыть» | `PatientIdentity.tsx` | раскрытие без необходимости | R-19 |
| Совмещение модальностей: измерения заблокированы до одобрения врачом | `ModalityRegistration.tsx` | измерение по неверному совмещению | R-09 |
| «Сообщить об инциденте…» на каждом исследовании | `ReportIncident.tsx` | ошибка не сообщена | R-22 |

## 3. Сценарии использования, связанные с опасностями

Сценарий — ошибка использования, которая может привести к вреду. Для каждого — критическая
задача итоговой оценки (п. 5).

| ID | Сценарий | Риск | Критическая задача |
|---|---|---|---|
| U-1 | Врач подтверждает черновик ИИ, не глядя на снимок (автоматическое доверие) | R-01 | К-1 |
| U-2 | Врач видит пустую серию и подписывает «норму», не прочитав снимок сам | R-03 | К-2 |
| U-3 | Модель отказалась (возраст, область), врач считает, что ИИ «ничего не нашёл» | R-03, R-07 | К-3 |
| U-4 | Врач принимает уверенность модели 90 % за вероятность болезни | R-01 | К-4 (опрос) |
| U-5 | Врач не понимает, в каком режиме система, и ждёт черновиков в SHADOW | R-16 | К-5 |
| U-6 | Врач не замечает предупреждение о несопоставленном пациенте и делает вывод о динамике | R-05 | К-6 |
| U-7 | Врач измеряет по совмещению, не проверив его | R-09 | К-7 |
| U-8 | Врач считает тепловую карту контуром патологии | R-04 | К-4 (опрос) |
| U-9 | Узбекское заключение понято клиницистом неверно | R-12 | отдельно — проверка носителем языка |

## 4. Формирующие оценки (выполнено)

Пока без врачей NCMC — эвристический разбор разработчиком при анализе рисков. Найдено и
исправлено (подробности — `ZHURNAL-RABOT.md`):

| Дата | Находка | Исправление |
|---|---|---|
| 4 окт. | «Находок нет» на пустой серии читалось как вывод ИИ «норма» | новая надпись (U-2) |
| 4 окт. | Отказ модели вне границ не показывался врачу — пустая серия неотличима от «ИИ не нашёл» | отказ с причиной на серии (U-3) |
| 4 окт. | Неоднозначное сопоставление пациента не показывалось никому | предупреждение и очередь (U-6) |
| 4 окт. | Время решения считалось от загрузки страницы — завышалось для карточек ниже экрана | отсчёт от появления карточки на экране |
| 1 окт. | Отмена отката модели не отменяла действие | исправлено ранее (форма с причиной) |

**Решить:** формирующая оценка с 2–3 врачами NCMC на стенде до пилота (разметка «думай
вслух» на 10–15 исследованиях из открытых наборов) — дешевле, чем находить ошибки в пилоте.

## 5. План итоговой оценки (в пилоте NCMC)

**Участники.** Все врачи-рентгенологи NCMC, работающие с платформой в пилоте, и 3–5
клиницистов. Ориентир FDA для итоговой оценки — 15 участников на группу пользователей; в
одном центре столько рентгенологов может не быть — **Решить с консультантом**, достаточно ли
одного центра или нужна вторая площадка.

**Когда.** Задачи К-1…К-3 и К-6 требуют видимых черновиков ИИ — то есть режима ASSIST.
Порядок: наблюдение в SHADOW (К-5, К-7, интерфейс без ИИ) → ограниченный ASSIST по решению
гейта и ответственного лица → наблюдение К-1…К-4, К-6.

**Критические задачи и критерии успеха** (критерии — предложение, **Решить** с врачами NCMC):

| Задача | Как наблюдаем | Успех |
|---|---|---|
| К-1. Принять решение по каждому черновику ИИ со сверкой со снимком | наблюдение 20 исследований на врача; данные платформы: доля подтверждений быстрее 3 с | нет подтверждений без взгляда на снимок; быстрых подтверждений ≤ 10 % |
| К-2. Описать серию без черновиков ИИ | наблюдение; данные: доля своих находок врача в исследованиях без черновиков | врач читает снимок сам; доля своих находок без черновиков не ниже, чем с черновиками |
| К-3. Распознать отказ ИИ и описать серию самостоятельно | подготовленные исследования вне границ (без возраста, взрослый) | 100 % врачей называют причину отказа |
| К-4. Объяснить, что значат уверенность модели и тепловая карта | опрос после сессии | верное понимание у всех; неверное — изменить надписи |
| К-5. Назвать текущий режим и что врач видит в нём | опрос | 100 % |
| К-6. Заметить предупреждение о несопоставленном пациенте | подготовленный случай на стенде | 100 % замечают и не делают вывода о динамике |
| К-7. Проверить совмещение до измерений | наблюдение | измерений по неодобренному совмещению нет (блокировка в коде) |

**Данные платформы** (`GET /pilot/usability`, «Пилот» → «Юзабилити»): число решений по
черновикам ИИ, время решения (медиана, 10–90 %), доля подтверждений быстрее 3 с, доля
собственных находок врача в подписанных исследованиях с черновиками ИИ и без них, время от
приёма до подписи. Только агрегаты по всем врачам: **оценивается изделие, не сотрудники**
(**Решить:** согласовать с NCMC и врачами до сбора).

**Ограничения данных.** Время решения — от появления карточки на экране до действия; врач мог
смотреть снимок в PACS-просмотрщике раньше, поэтому быстрое подтверждение — **сигнал для
наблюдения**, а не доказательство ошибки. «Свои находки врача» в исследованиях без черновиков
бывают и у нормальных снимков нулевыми — сравнивается с долей при черновиках, на объёме.

**Итог.** Отчёт об итоговой оценке: участники, задачи, наблюдённые ошибки использования,
их корневые причины, изменения интерфейса, повторная проверка; пересчёт R-01 и R-03 в файле
рисков.
