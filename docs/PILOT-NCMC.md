# Пилот на National Children Medical Center: чек-лист

Пилот идёт в режиме **SHADOW/RESEARCH**: платформа принимает снимки, копит статистику
и правки врачей, но клинических решений по ней не принимают. Переход в ASSIST — только
после локальной валидации отдельно по детям (раздел 9 ТЗ).

Отмечайте пункты по мере выполнения. Кто делает: **ИТ** — ИТ-служба NCMC,
**Р** — ответственный рентгенолог, **Мы** — команда разработки.

## 0. Демонстрация без PACS и GPU (1 день)

- [ ] **ИТ** Сервер: Linux, 8 CPU, 32 ГБ ОЗУ, 500 ГБ диска, Docker + Compose.
- [ ] **ИТ** `cp .env.example .env`, заменить все `change_me_*` на сложные пароли.
- [ ] **ИТ** Заранее проверить доступность образов: `docker compose pull`. Если `minio/minio`
      не скачивается (MinIO ограничивает публикацию бесплатных образов), указать в `.env`
      `MINIO_IMAGE` — зеркало или другое S3-совместимое хранилище.
- [ ] **ИТ** `make up && make migrate && make seed`.
- [ ] **ИТ** Вход врачей (Keycloak): в `.env` — `KEYCLOAK_PUBLIC_URL=http://<IP сервера>:8080`,
      `ALLOW_DEBUG_AUTH=false`; `make up`, затем `make keycloak-configure`.
- [ ] **ИТ** Учётные записи: `http://<IP сервера>:8080/admin` → realm `medviz` → Users →
      создать сотрудника → Role mapping: `radiologist` / `clinician` / `admin` / `researcher` /
      `auditor`. Пароли — только лично сотруднику, не в чатах и не в документах.
- [ ] **ИТ** Рабочие места врачей открывают `http://<IP сервера>/` (шлюз: интерфейс, API,
      DICOMweb). Просмотрщик OHIF — `http://<IP сервера>:3000/`, кнопка «Открыть в
      просмотрщике» в разборе исследования. Порты 80 и 3000 — только для сети клиники.
- [ ] **Р** Войти как radiologist, открыть исследование «Рентгенография ОГК (демо)»:
  - черновики ИИ с уверенностью; кнопка «Зона внимания ИИ» показывает карту;
  - подтвердить одну находку, отклонить другую, заменить код третьей;
  - собрать и подписать заключение.
  - «Показать данные пациента» (с указанием цели) — ФИО и номер карты видны только
    врачу на экране, каждый просмотр записан в журнал аудита (раздел «Журнал»).
- [ ] **Р** Админка → модель `demo_cxr_peds 0.2.0` (SHADOW) → «Сравнить с заключениями».
- [ ] Всё демо — синтетика: реальных данных пациентов нет.

## 1. Подключение к PACS (см. `PACS-NCMC.md`)

- [ ] **ИТ** IP сервера платформы в сети больницы (та же подсеть, что HIPACS `10.0.0.30`).
- [ ] **ИТ** Открыть порт 4242 (DICOM) сервера платформы **только** для `10.0.0.30`.
- [ ] **ИТ** В H-PACS добавить узел `MEDVIZ_RAW` / IP платформы / `4242`.
- [ ] **ИТ** `make check-pacs` — C-ECHO успешен.
- [ ] **ИТ** Сменить пароль PACS (сейчас слабый) — до подключения.
- [ ] **Р** Отправить 1 тестовое исследование → появилось в worklist **обезличенным**
      (цепочка: H-PACS → orthanc-raw → сервис `orthanc-watcher` → обезличивание → анализ;
      при задержке смотреть `docker compose logs orthanc-watcher worker`).
- [ ] **Мы** Проверить, что H-PACS передаёт **BodyPartExamined** (0018,0015) и кодировку
      (SpecificCharacterSet, для кириллицы — ISO_IR 192 или ISO_IR 144). Без области
      исследования модели отказывают (SR-7), если описание не содержит «ОГК»/«грудн…».
- [ ] **Мы** Проверить, что в DICOM NCMC заполнен **PatientAge** (0010,1010). Без возраста
      серии не проходят гейт применимости и не идут в обучение.
- [ ] **Мы** Проверить описания протоколов: «ОГК», «Chest», «грудн…» распознаются как
      грудная клетка. Прислать нам список незнакомых описаний (без данных пациентов).

## 2. Первая модель (офлайн, на отдельном GPU-сервере; см. `TRAINING.md`)

- [ ] **ИТ** Обучающий сервер с GPU ≥ 24 ГБ, `MEDVIZ_CONTOUR=training`.
- [ ] **Р/Мы** Доступ PhysioNet (CITI + DUA) → скачать VinDr-PCXR (+ MIMIC-CXR-JPG, VinDr-CXR).
- [ ] **Юрист** Лицензии датасетов для коммерческого медизделия.
- [ ] **Мы** `manifest` → прислать нам **только** `*.report.json`.
- [ ] **Мы** `freeze` → `train --population pediatric` → `evaluate`.
- [ ] **ИТ** Скопировать `model.pt` в `models/<weights_hash>.pt` на сервере платформы.
- [ ] **ИТ** `.env`: `WORKER_EXTRAS=[infer]`, затем `docker compose build worker && docker compose up -d worker`.
- [ ] **Админ** Админка → вставить `registration.json` → кандидат в **SHADOW**.

## 2а. Старт теневого прогона без GPU (сразу после подключения PACS)

- [ ] **ИТ** `.env`: `WORKER_EXTRAS=[infer]`, `docker compose build worker`, `make xrv-candidate`.
- [ ] **Админ** Зарегистрировать `models/xrv_all-*.registration.json` → SHADOW.
- [ ] **ИТ** `make totalseg-candidate` → зарегистрировать `models/totalseg_ct_fast-*.registration.json`:
      сегментация органов КТ (~1 мин на исследование на CPU) в теневом прогоне.
      Для МРТ: `docker compose run ... scripts/totalseg_candidate.py --task total_mr` → `totalseg_mr_fast`.
- [ ] **Админ** Через 4–6 недель: «Калибровка по площадке» → новый кандидат с порогами NCMC.
      Подробности и ограничения — `TRAINING.md`, раздел 7.

## 3. Теневой прогон (8–12 недель)

Прогресс виден на странице **«Пилот»** (роли admin/auditor): исследования, решения
врачей, подписанные заключения и отказы ИИ по неделям; доля принятых черновиков;
расхождения кандидатов; накопленные обучающие метки; причины отказов. Только агрегаты.

- [ ] **Р** Врачи работают как обычно и **подписывают заключения в платформе** —
      только подписанные исследования участвуют в сравнении и дают полные метки.
- [ ] **Р** Врачи добавляют свои находки из словаря ОГК (без этого модель не узнает о пропусках).
- [ ] **Админ** Раз в 2 недели: «Сравнить с заключениями» — расхождения и пропуски
      по находкам и по аппаратам. Рост на одном аппарате → разбор (FR-11).
- [ ] **Мы** Раз в месяц: `POST /learning/site-manifest` → `import-site` → дообучение →
      новый кандидат в SHADOW. Замороженный тест площадки формируется **один раз**.

## 4. Решение о переходе в ASSIST (только для детского рентгена ОГК)

- [ ] Замороженный тест площадки ≥ 100 исследований, кандидат не хуже действующей модели.
- [ ] Доля расхождений в теневом прогоне ≤ 15% (порог согласуется до этапа 5).
- [ ] Нет деградации на аппаратах, не участвовавших в обучении.
- [ ] Локальное валидационное исследование по детям оформлено (раздел 9).
- [ ] Письменное обоснование ответственного лица → «Продвинуть» в админке.
- [ ] Откат проверен на стенде: «Откатить» возвращает предыдущую версию сразу.

## Что система делает сама, а что — никогда

| Сама | Никогда |
|---|---|
| Обезличивает каждый снимок на входе | Не выставляет диагноз и не пишет «норма» |
| Отказывает вне границ применимости (возраст, модальность) | Не включает находку в заключение без врача |
| Прогоняет кандидатов в тени, скрывая результат | Не показывает врачу результаты теневого прогона |
| Копит правки врачей как обучающий сигнал | Не обучается на продуктивном сервере |
| Показывает уверенность и зону внимания как подсказку | Не подменяет модель без решения ответственного лица |
| Работает без ИИ: просмотр не зависит от моделей | Не запускает заглушку вместо настоящих весов |
