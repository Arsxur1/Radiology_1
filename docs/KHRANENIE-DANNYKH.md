# Политика хранения и удаления данных (проект)

**Проект для юристов NCMC и разработчика.** Дополняет `PRILOZHENIE-DANNYE-NCMC.md`
(п. 6 «Решить: сроки хранения… порядок удаления по окончании договора»). Для каждой
категории данных указано, где она лежит, зачем нужна, **что платформа делает уже сейчас**
(проверено кодом и тестами) и **предлагаемый срок**. Сроки — предложения: правовые
источники РУз о сроках хранения медицинской документации и о сроках обработки персональных
данных (закон ЗРУ-547) из среды разработки недоступны (lex.uz закрыт сетевой политикой), поэтому
ни одна цифра ниже не выдаётся за требование закона. Места, требующие решения, отмечены
**«Решить»**.

Редакция от 4 октября 2026 г.

## 1. Принципы

1. **Сначала — то, что указывает на ребёнка.** ФИО, номер карты и исходные UID хранятся
   минимально: сырой объект удаляется сразу после обезличивания, связь «псевдоним ↔
   личность» — в отдельном контуре; при прекращении хранения он уничтожается первым.
2. **Медицинские данные платформы — вторичная копия.** Оригиналы снимков и подписанные
   заключения (DICOM SR) — в PACS NCMC. Срок хранения платформы не должен превышать нужный
   для работы врача (сравнение в динамике) и для контроля качества моделей.
3. **Аудит и инциденты храним дольше данных**, к которым они относятся: они доказывают, кто
   и что делал с данными, и нужны для расследований и надзора после регистрации.
4. **Удаление проверяемо:** инвентаризация до и после (`scripts/data_inventory.py`,
   `GET /system/data-inventory`) — только счётчики и даты, без идентификаторов; её можно
   приложить к акту.

## 2. Категории, сроки, механизмы

| Категория | Где | Что делает платформа сейчас | Предлагаемый срок |
|---|---|---|---|
| Сырой DICOM с ФИО, принятый от PACS | `orthanc-raw` | удаляется сразу после обезличивания (`RAW_DELETE_AFTER_INGEST=true`); застрявшие дольше 10 мин — в «Состоянии системы» | минуты; застрявшие — разбор в тот же день |
| Сырой DICOM с ФИО из сетевой папки | том `ingest_data` | **с 4 октября** удаляется после загрузки в приёмник (`INGEST_DELETE_AFTER_UPLOAD=true`); не загрузившиеся — в «Состоянии системы»; имена файлов в лог не пишутся | минуты; застрявшие — разбор в тот же день |
| Связь «псевдоним ↔ ФИО, номер карты, исходные UID» | БД `medviz_idmap` | раскрытие только по цели с аудитом | пока хранятся обезличенные данные пациента; **первым** уничтожается при удалении |
| Ключ псевдонимизации `PSEUDONYM_KEY` | сервер, зашифрованная копия | без ключа обезличивание запрещено | весь срок работы; уничтожение ключа делает оставшиеся псевдонимы необратимыми |
| Обезличенные снимки и производные (маски, тепловые карты, 3D, совмещения) | `orthanc-clean`, хранилище объектов | бессрочно | **Решить:** предложение — срок действия договора, но не дольше срока хранения медицинской документации NCMC; по истечении — удаление вместе с метаданными |
| Метаданные исследований, находки, заключения | БД `medviz` | бессрочно | как снимки |
| Решения врачей как обучающие метки | БД `medviz` | **с 4 октября** — исключение пациента из обучения по отзыву согласия (п. 3) | как снимки; использование для обучения — пока действует основание |
| Журнал аудита | БД `medviz` | только добавление (права СУБД), платформа не удаляет | **Решить:** предложение — не меньше срока хранения медицинских данных, к которым он относится; перед удалением — выгрузка CSV и передача NCMC |
| Инциденты, версии моделей и свидетельства гейта | БД `medviz` | бессрочно | **Решить с консультантом:** срок надзора после регистрации (срок жизни изделия + период, установленный регулятором) |
| Учётные записи сотрудников | БД Keycloak | события входа — 90 дней (`eventsExpiration` 7 776 000 с) | учётная запись — пока сотрудник работает; при увольнении — блокировка, затем удаление (**Решить:** срок) |
| Резервные копии | диск копий NCMC | 14 последних (`BACKUP_KEEP`); базы и ключ — зашифрованы | удалённое из платформы исчезает из копий через 14 дней — это срок «полного забвения» |
| Логи контейнеров | Docker | **с 4 октября** ротация: 5 файлов по 50 МБ на сервис (`LOG_MAX_SIZE`, `LOG_MAX_FILE`) | несколько недель; идентификаторы пациентов в логи не пишутся |
| Результаты фоновых задач | Redis | сутки (`result_expires`) | сутки |
| Обучающие выгрузки | обучающий сервер | выгрузка — с аудитом, без серий с риском текста на снимке и без исключённых пациентов | **Решить:** удаляются после обучения версии; при отзыве согласия — исключение из следующей выгрузки |
| Сводные отчёты (`*.report.json`, «Пилот», инвентаризация) | у разработчика | только агрегаты | без ограничения (не персональные данные) |

## 3. Отзыв согласия на использование для обучения

Если основанием цели 2 приложения к договору (улучшение моделей) выбрано согласие законных
представителей, отзыв согласия исполняется так:

- администратор находит пациента («Пациенты» → поиск по номеру карты или ФИО — сравниваются
  ключевые токены) и отмечает «Исключить из обучения» с основанием из списка (свободного
  текста нет — в нём легко оказаться ФИО); отметка и её снятие — в журнале аудита;
- исследования пациента **не идут** в выгрузку меток площадки, выгрузку правок врачей и
  калибровку порогов; в «Пилоте» видно число исключённых серий;
- отметка сохраняется при объединении записей (если исключена любая из двух) и
  наследуется при разъединении;
- **не затрагивается:** работа врача (просмотр, находки, заключение — это медицинская
  помощь) и контроль качества моделей на подписанных заключениях (теневой прогон —
  безопасность пациентов). **Решить с юристом:** допустимо ли использовать данные для
  контроля качества после отзыва согласия на обучение;
- уже обученную модель «разучить» нельзя: исключение действует для следующих версий; версия
  модели и дата выгрузки известны из аудита.

Проверено: `test_training_exclusion.py`; вживую на стенде — 4 октября (`ZHURNAL-RABOT.md`).

## 4. Удаление по окончании договора

Порядок (выполняет ИТ NCMC вместе с разработчиком, по акту):

1. **Инвентаризация «до»:** `docker compose run --rm backend python scripts/data_inventory.py
   > inventory-before.json` — приложить к акту.
2. **Передать NCMC то, что остаётся у клиники:** журнал аудита — «Журнал» → выгрузка CSV;
   заключения уже в PACS NCMC (DICOM SR); список инцидентов — страница «Инциденты».
3. Остановить передачу исследований из PACS (настройка PACS), убедиться, что
   `orthanc-raw` и папка приёма пусты («Состояние системы»).
4. **Идентифицирующий контур — первым:** остановить платформу и удалить том
   идентифицирующей базы (`<проект>_pg_idmap_data`, см. `docker volume ls`).
5. Удалить остальные тома платформы: `docker compose down -v` (базы, снимки, хранилище
   объектов, очередь, учётные записи, папка приёма).
6. **Уничтожить ключи:** `PSEUDONYM_KEY`, ключ бэкапа, файл `.env`, TLS-ключи шлюза.
7. **Резервные копии:** удалить с диска копий; диск копий зашифрован средствами ОС —
   уничтожить и его ключ.
8. Обучающий сервер (если отдельный): удалить выгрузки и промежуточные файлы; в акте —
   список удалённых выгрузок по журналу аудита.
9. **Проверка «после»:** `docker volume ls | grep medviz` — пусто; каталог копий пуст;
   инвентаризация невозможна (баз нет) — отметить в акте.

У разработчика остаются только сводные отчёты (агрегаты) и веса моделей. **Решить:**
остаются ли у разработчика веса моделей, дообученных на данных NCMC (договор).

## 5. Ежегодная проверка

Раз в год (и перед продлением договора): инвентаризация, сверка сроков с таблицей п. 2,
проверка «Состояния системы» (папка приёма, застрявшие в приёмнике, бэкап), отчёт
ответственному за персональные данные NCMC.

## 6. Что решить

1. Срок хранения обезличенных снимков и медицинских данных платформы (п. 2) — по сроку
   хранения медицинской документации NCMC.
2. Срок хранения журнала аудита и инцидентов (с регуляторным консультантом — для надзора
   после регистрации).
3. Правовое основание цели 2 (обучение) и судьба данных для контроля качества после
   отзыва согласия (п. 3).
4. Срок удаления учётных записей уволенных сотрудников.
5. Судьба весов моделей, дообученных на данных NCMC, после окончания договора.
6. Срок хранения обучающих выгрузок на обучающем сервере.
