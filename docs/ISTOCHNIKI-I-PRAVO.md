# Источники данных, лицензии и нормы Узбекистана

Сводка из первоисточников, проверено **1 октября 2026**. Это рабочая справка разработки,
не юридическое заключение: решение о коммерческом применении — за юристом (PILOT-NCMC,
раздел 2). Что подтверждено по первоисточнику, а что — по вторичным, указано явно.

Машиночитаемая версия реестра данных — `backend/app/services/data_provenance.py`; гейт
продвижения применяет её автоматически (см. ниже).

## 1. Главный вывод по данным

**Все наборы PhysioNet из нашего плана (VinDr-PCXR, VinDr-CXR, MIMIC-CXR-JPG) разрешены
только для научных исследований** («lawful use in scientific research and no other»,
п. 6 лицензий PhysioNet 1.5.0). Модель, обученная на них, годится для теневой оценки и
публикаций, но **не для клинического применения в коммерческом медизделии**. Для ASSIST
нужны веса на коммерчески допустимых данных и/или дообучение на данных NCMC (по договору
с клиникой).

Хорошая новость: **VinDr-PCXR (дети) — уровень «Restricted», а не «Credentialed»**. Нужны
только учётная запись PhysioNet и подпись DUA, курс CITI не требуется. Это быстрый путь
к педиатрическому набору для научной валидации.

Как использовать:
- **HWCMC (Hainan)** — открытый детский рентген с коммерчески допустимой лицензией и
  возрастом **0–14 лет**, ближе всего к пациентам NCMC; пять классов (норма и четыре типа
  пневмонии). Метки — диагнозы: годится для проверки и педиатрической адаптации, не для
  словаря находок.
- **Kermany** — второй открытый детский рентген с коммерчески допустимой
  лицензией (1–5 лет; на Zenodo — в версии PneumoniaMNIST+ 224×224). Метки — диагнозы («пневмония/норма»); по SR-1 диагноз не выдаём, поэтому
  набор годится для педиатрической адаптации и проверки «норма / не норма», а не для
  словаря находок.
- **Pediatric-CT-SEG** — эталон для проверки сегментации КТ именно у детей (объёмы
  органов у NCMC). Нужно подтвердить лицензию коллекции на сайте TCIA (обычно CC BY 4.0).
- **NIH ChestX-ray14** — коммерчески допустим, но взрослые; основа xrv-весов `-nih`.

Результаты проверки открытых моделей на этих детских наборах — `VALIDATSIYA-DETI.md`.

## 4. Как это применяет платформа

- У каждой модели хранится происхождение обучающих данных: для xrv/TotalSegmentator — по
  весам, для своих моделей — `training_data` из карточки (`train.py` пишет наборы и
  `imagenet` для стартовых весов).
- **Гейт продвижения отказывает**, если среди данных есть «только для исследований», с
  объяснением и вариантами (веса `-nih`, данные площадки).
- Если права не подтверждены («unknown»), гейт не блокирует, но в свидетельствах —
  пометка «решение за юристом до продвижения». Админка показывает строку «Обучающие данные».

## 5. Нормы Узбекистана

**Закон о персональных данных (ЗРУ-547), изменения в силе с 27.03.2026.** Обязательное
хранение только в Узбекистане теперь — для биометрических и генетических данных и данных
абонентов местных операторов связи. Прочие данные можно хранить за рубежом при условиях
(страна с адекватной защитой, стандартные договорные положения и др.)
([Dentons](https://www.dentons.com/en/insights/articles/2026/march/31/uzbekistan-dismantles-strict-data-localization-regime),
[Settle Advisory](https://settleadvisory.com/news-en/localization-of-personal-data-in-uzbekistan-transition-to-a-more-flexible-regulatory-model/)).
Для нас ничего не меняется: платформа и так работает внутри клиники, PHI не покидает
контур (SR-9), наружу уходят только сводные отчёты. Вопрос «можно ли обучать за рубежом на
обезличенных данных NCMC» — к юристу (обезличенные данные могут не считаться персональными).

**Закон об ИИ ЗРУ-1115 от 21.01.2026** (поправки в действующие законы) и этические правила
(в силе с 17.06.2026) ([обзор](https://axipro.co/uzbekistan-ai-regulation/)):
- запрет решений, влияющих на права человека, только на основании выводов ИИ — у нас
  выполнено по построению (SR-2: каждое включение — активное действие врача, автопринятия нет);
- **обязательная маркировка информации, созданной с использованием ИИ** — сделано:
  подписанное заключение (печатная форма и DICOM SR в PACS) указывает систему и версию
  модели и помечает каждый пункт «ИИ → подтверждено врачом» или «врач»;
- штрафы за незаконную обработку персональных данных с помощью ИИ — см. SR-9.

**Регистрация медизделий: Постановление Кабмина № 738 от 24.11.2025, в силе с 26.02.2026**
([lex.uz](https://lex.uz/en/docs/7861699?ONDATE=26.02.2026)). Регистрирует Центр безопасности
фармацевтической продукции при Минздраве (uzpharm-control.uz); для изделий с ПО нужны отчёты
верификации и валидации ПО; срок регистрации 6–12 месяцев по классу, действует 5 лет;
изделия с одобрением FDA / CE / PMDA / MFDS / MHRA — упрощённый путь без местных
лабораторных испытаний (по вторичным источникам:
[Legal 500](https://www.legal500.com/developments/thought-leadership/new-rules-of-state-registration-of-medicinal-products-and-medical-devices-in-the-republic-of-uzbekistan/),
[Elendi Labs](https://elendilabs.com/en/articles/uzb-uzpharm-medical-device-state-registration)).
Текст постановления на lex.uz из среды разработки недоступен — юристу проверить по
первоисточнику. Наши материалы для V&V ПО: `TRACEABILITY.md`, `ACCEPTANCE.md`, тесты и CI,
журнал работ.
