# Этап 2: сегментация, измерения, 3D, захват правок

Первая клиническая область — **КТ грудной клетки** (согласовано с заказчиком).
Режим — `RESEARCH` (раздел 8). Модели не ставят диагноз: они выдают структуры и
измерения, которые врач подтверждает/правит/отклоняет.

## Контур инференса

```
   Приём серии (FR-1)
        │  авто-триггер после приёма (FR-3)
        ▼
  ┌──────────────────────────┐
  │  Гейт применимости (SR-7) │  check_applicability()
  │  services/applicability   │  вне диапазона → ЯВНЫЙ ОТКАЗ с причиной,
  └───────────┬──────────────┘  результат НЕ пишется
              │ допущено
              ▼
  ┌──────────────────────────┐  адаптер модели
  │  Инференс                 │  TotalSegmentator (стенд) | Stub (без GPU)
  │  services/inference_adapters
  └───────────┬──────────────┘
              ▼
  ┌──────────────────────────┐  детерминированно (FR-6)
  │  Измерения                │  объём, линейные размеры, плотность, соотношения
  │  services/measurements    │  повторный запуск → тот же результат
  └───────────┬──────────────┘
              ▼
  ┌──────────────────────────┐  SR-5: версия модели, хеш весов, серия, препроцессинг
  │  inference_result + findings  source=model, status=PENDING («не подтверждено»)
  └───────────┬──────────────┘
              │
    режим SHADOW → врачу не показываются (раздел 2, mode_state.py)
    режим RESEARCH/ASSIST → видны как черновик
              ▼
  ┌──────────────────────────┐
  │  Правки врача (FR-9)      │  confirm / modify / reject / add → correction
  │  услуги контура обучения  │  (см. docs/LEARNING-LOOP.md)
  └──────────────────────────┘
```

## Гейт применимости (SR-7)

Границы применимости хранятся в `model_version.applicability` (JSONB). Пример для
модели КТ грудной клетки, только взрослые:

```json
{
  "modality": ["CT"],
  "body_part": ["CHEST", "THORAX"],
  "slice_thickness_mm": {"max": 3.0},
  "age": {"min_years": 18},
  "manufacturers": ["Siemens", "GE", "Philips", "Canon"],
  "allow_lossy": false,
  "require_contrast": null
}
```

Серия вне диапазона получает **отказ с перечнем причин**, а не результат «с
пониженной уверенностью». Отсутствие обязательного для проверки поля (возраст,
толщина среза) трактуется в пользу отказа (раздел 11).

## Детерминированные измерения (FR-6)

`services/measurements.py` — только чистые функции: объём = число вокселей ×
объём вокселя; плотностная статистика по фиксированному порядку. Повторный запуск
на той же серии той же версией даёт идентичный результат (критерий приёмки,
раздел 10). Тесты — `test_measurements.py`.

## 3D-модели (FR-5)

`services/mesh.py::can_build_mesh` — гейт: строим только из **подтверждённых**
масок и только при достаточной толщине среза и отсутствии сжатия с потерями;
иначе отказ с причиной. Геометрия (marching cubes → сглаживание → дециматия,
экспорт glTF/Draco и STL) подключается на стенде.

## Подключение реальной модели (TotalSegmentator)

1. Стенд с GPU (см. VOPROSY-K-TZ.md, п. 15–16).
2. Реализовать `TotalSegmentatorAdapter.infer()`: загрузка серии из объектного
   хранилища → инференс → маска (DICOM SEG/NIfTI в MinIO) → воксельная статистика.
3. Проверить лицензию конкретных весов (VOPROSY-K-TZ.md, п. 34); при необходимости
   дообучить собственные веса на собранных данных.
4. Зарегистрировать версию (`POST /models/candidates`) с границами применимости;
   модель стартует в `SHADOW`.
5. Заполнить `weights_hash` реальным хешем весов (SR-5).

Переход к клиническому применению — только через критерии раздела 9 и гейт
продвижения (`docs/LEARNING-LOOP.md`).

## API этапа 2

| Метод | Назначение |
|---|---|
| `POST /segmentation` | Запустить сегментацию серии (отказ SR-7 → 422 с причинами) |
| `GET /findings/series/{id}` | Находки серии (в SHADOW результаты модели скрыты) |
| `POST /findings/{id}/confirm\|modify\|reject` | Решение врача → correction |
| `POST /findings` | Добавить пропущенную моделью находку |
