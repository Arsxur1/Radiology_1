# Проверка критериев приёмки (раздел 10 ТЗ)

Критерии приёмки автоматизированы тестами и прогоняются в CI. Часть проверок
(неизменяемость аудита на уровне СУБД, восстановление из бэкапа) требует
PostgreSQL/стенда и отмечена отдельно.

| Критерий (раздел 10) | Как проверяется | Где |
|---|---|---|
| Полная трассируемость: восстановимы версия модели, входные данные, правки | Интеграционный тест: `inference_result` ссылается на версию модели, серию, препроцессинг; находка — на inference | `test_acceptance_criteria.py::test_traceability_inference_and_findings` |
| Воспроизводимость: та же версия на той же серии → тот же результат | Детерминизм измерений и обезличивания | `test_reproducibility_measurements`, `test_reproducibility_deidentification` |
| Отказ вне границ применимости, а не результат | Педиатрия для взрослой модели → `ApplicabilityRefused`, находки не создаются | `test_refusal_out_of_range`, `test_integration_flow.py::test_flow_refuses_out_of_range` |
| Деградация при отключении ИИ не ломает просмотр | Изоляция воркеров; `GET /ready` (ai отдельно); автосегментация — no-op без активной модели | `routes_health.py`, `segmentation_tasks.py` |
| Невозможность подмены аудит-лога средствами приложения | Хеш-цепочка обнаруживает подмену; на PostgreSQL — триггер + REVOKE (миграция 0002) | `test_audit_chain_intact`, `test_audit_chain_detects_tampering`; `GET /audit/verify` |
| Восстановление из бэкапа на чистом сервере | Скрипт бэкапа + проверка восстановления на стенде | `scripts/backup.sh` (проверка — на стенде) |

## Сквозной путь (интеграция)

`test_integration_flow.py` прогоняет ключевую цепочку целиком на реальной БД:

```
пациент → исследование → серия → активная модель → сегментация (SR-7 гейт)
       → находки (model, PENDING) → правки врача (FR-9) → correction
       → сравнение во времени (FR-7) → черновик из подтверждённых (FR-8)
       → финализация (SR-2)
```

Проверяемые инварианты: находки модели не подтверждены по умолчанию; черновик
пуст без подтверждённых находок; каждая правка порождает `correction`; динамика
считается по подтверждённым находкам; финализация фиксируется врачом.

## Запуск

```bash
cd backend && pytest -q            # все тесты, включая интеграционные и приёмочные
pytest -q tests/test_acceptance_criteria.py
pytest -q tests/test_integration_flow.py
```

Тесты используют in-memory SQLite через переносимые типы (`app/db/types.py`):
модели те же, что в продакшне; поведение PostgreSQL (нативные UUID/JSONB, триггер
аудита, права ролей) не меняется и проверяется дополнительно на стенде.
